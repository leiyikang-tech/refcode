# repo-map harness

The deterministic execution layer behind **Operation 1 (`/init-deep`)** of the
**repo-map** skill. It makes the AGENTS.md knowledge-base generation autonomous
and quality-gated with pure scripts:

- `refresh_state.py` — durable run state (init / gate / resume / status / finish).
- `gates.py` — six deterministic quality gates (no LLM judgment in pass/fail).
- `cleanup.py` — post-analysis byproduct cleanup (compile artifacts + git
  history compaction + /tmp scratch), safe: never deletes tracked source.

Both are Python 3 stdlib-only. No dependencies.

> Scope note: G1–G5 gate **Op1 (init-deep, the hierarchical AGENTS.md base)**,
> because they check file-system facts (analyzable / stack / docs produced /
> structure / builds). **G6 (INDEXED)** gates the indexing half of **Op5** — the
> analyzed project itself must be in the shared refcode corpus with a live
> `ref_symbols` hit before any deliverable is pushed. Op2 (profile) and Op3
> (comparative research) judge *semantic* truth, so their pass/fail gates live in
> the playbooks as content gates (`references/op2-profile.md`,
> `references/op3-research.md`) — not here.

## Layout

```
harness/
  refresh_state.py   state backbone (run.json owner)
  gates.py           G1–G6 deterministic gates
  cleanup.py         post-analysis byproduct cleanup (safe)
  run.json           active run state (created by `init`, re-generated by install)
  README.md          this file
```

## Quick start

```bash
H=/root/.sisyphus/repo-map/harness

# 1. start a fresh run against a repo
python3 $H/refresh_state.py init --repo /path/to/repo [--out <run-dir>]

# 2. after DISCOVERY: gate it, persist only on PASS
python3 $H/gates.py g1 --repo /path/to/repo
python3 $H/refresh_state.py gate g1 --out <run-dir> --result PASS

# 3. as each phase completes, gate + persist (g2…g5)
#    NOTE: persist under the harness's own keys g1..g6 — never hand-write Q1..Q5
python3 $H/gates.py g2 --repo /path/to/repo --stack node
python3 $H/refresh_state.py gate g2 --out <run-dir> --result PASS

# 3b. Op5 FIRST HALF — index the analyzed project, then gate g6
python3 $H/gates.py g6 --repo /path/to/repo    # 0 PASS / 1 FAIL / 2 BLOCKED
python3 $H/refresh_state.py gate g6 --out <run-dir> --result PASS
#     on 1: refcode index <slug> /path/to/repo --licence <SPDX>  -> re-run g6

# 3c. close the run — refuses unless g1..g6 are all PASS (--force -> PARTIAL)
python3 $H/refresh_state.py finish --out <run-dir> --summary "<one line>"

# 4. crash mid-run? resume at the failed gate (use the same --out as init)
python3 $H/refresh_state.py resume --out <run-dir>
```

## Cleanup after a closed run (space reclaim)

Analysis leaves disposable byproducts. After `finish` (and Op5 push) succeeds,
reclaim disk on the analyzed repo with `cleanup.py`:

```bash
# safe dry-run first: prints exactly what would be removed, changes nothing
python3 $H/cleanup.py --repo /path/to/repo --dry-run

# all three categories, live (no flag == all on)
python3 $H/cleanup.py --repo /path/to/repo

# a single category at a time
python3 $H/cleanup.py --repo /path/to/repo --artifacts   # compile artifacts + caches
python3 $H/cleanup.py --repo /path/to/repo --gc          # compact git history
python3 $H/cleanup.py --repo /path/to/repo --tmp         # /tmp repo-map scratch
```

Safety guarantees (non-negotiable):
- **`--artifacts`** deletes a candidate (`__pycache__`/`*.pyc`, `node_modules`,
  `.venv`/`venv`, `target`, `.gradle`, `dist`/`build`, `dependencies/`,
  `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, ...) ONLY when it is **not
  tracked by git** (`git ls-files`). A directory is deleted only when nothing
  under it is tracked, so a `dist/`/`build/` holding committed files is left
  intact. A tracked source file is always skipped.
- **`--gc`** only COMPACTS history (`git reflog expire --expire=now --all` +
  `git gc --aggressive --prune=now`). It never rewrites or drops commits, so
  Refresh-mode diffs against `last_analyzed_sha` keep working.
- **`--tmp`** only touches paths under the system temp root matching known
  repo-map scratch names (`/tmp/work-log-clone`, `/tmp/work-log`,
  `/tmp/corpus*.json`, ...). Nothing outside /tmp is removed.

Exit codes: `0` = success, `1` = error (repo missing / gc failed).

> `--out <run-dir>` is **optional and must be consistent across a given run**.
> Each state command (init/gate/resume/status/finish) accepts it; the default is
> the harness dir itself (single running repo). Pass `--out /some/dir` to hold a
> run.json for a second repo without clobbering the first.

## Gate exit codes

`gates.py <g1|g2|g3|g4|g5|g6> --repo <path>` returns:

| code | meaning | orchestrator does |
|------|---------|-------------------|
| 0 | PASS | persist via `refresh_state.py gate <g> --result PASS`; advance |
| 1 | FAIL | `gate <g> --result FAIL --note "<why>"`; rework |
| 2 | BLOCKED | 3 attempts exhausted → escalate to oracle → ABORT |
| 3 | SKIP (G5) | `gate g5 --result PASS --note "<reason for skip>"`; acceptable only recorded |

## Gate semantics (gates.py)

| gate | checks | PASS if |
|------|--------|---------|
| g1 | entrypoints / manifests / ≥10 source files | repo is analyzable |
| g2 | stack via manifest OR dominant-language census | stack is known |
| g3 | root KB >1KB + every `--dirs` doc non-empty | docs were produced |
| g4 | ≥1 doc, no zero bytes, no >200KB, internal `](file)` links resolve | docs are sound |
| g5 | per-stack build/lint/test under `bash -o pipefail` | build/tests clean |

`--out` defaults to repo (docs written in place). `--dirs` = comma-separated
absolute subdir paths scored for per-directory docs.

## State file shape (run.json)

```json
{
  "repo": "/abs/path",
  "phase": "scoring",
  "gates": {
    "g1": {"result": "PASS", "attempts": 0, "note": ""},
    "g2": {"result": "FAIL", "attempts": 1, "note": "inconclusive"}
  },
  "artifacts": {"dirs": [], "root_kb": "", "stack": ""},
  "summary": ""
}
```

Guarantees:
- A gate only advances when it PASSes (`refresh_state.py gate`).
- Attempt counters are monotonic — a later PASS never resets a remembered FAIL,
  so a crash-resume sees the true attempt history.
- `finish --summary` REFUSES to close a run while any of `g1..g6` is not PASS
  (exit 1, unmet gates listed). `--force` closes it as `result: PARTIAL`.
- A `run.json` carrying legacy `Q1..Q5` keys (or no `gates` dict) is normalised
  to `g1..g6` on the next `gate` call, so a hand-written state file cannot leave
  the `g6` slot silently empty.

## Abort protocol

On BLOCKED (3 attempts) or an interrupted run:
1. Escalate to a consultation agent (oracle) once for a fresh approach.
2. If still blocked or the run is abandoned: write `harness/ABORTED.md` with,
   for each gate, its final result + attempt count + note. Stop there —
   a visible partial failure, never a silent hang.

## Re-runnability

Re-running `init` refuses to overwrite an existing `run.json`. To re-run from
scratch against the same repo, delete `run.json` (or pass `--out <fresh-dir>`
to init a second run in its own dir). Both scripts are idempotent at the gate
level: re-running `gates.py gX` recomputes and can be persisted again.
